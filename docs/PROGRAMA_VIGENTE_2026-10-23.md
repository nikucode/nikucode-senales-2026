## Entrega y trabajo

- Un repo nuevo creado en el evento, público. El mismo puede contener código y `docs/` revisados; no se exige un segundo repo de investigación.
- Cada integrante usa su propia cuenta de GitHub para conservar atribución real. No inventar autorías ni compartir credenciales.
- README de una página: qué problema, por qué ese y no otro, qué dejaron fuera.
- Demo en vivo obligatoria; el formato es libre y el funcionamiento observado tiene prioridad sobre explicaciones.
- Casos construidos sin datos personales reales. El problema del sexto caso se relata sin cargar información identificadora o clínica.
- Herramientas y agentes permitidos. Investigación/material previo siguen con la autorización oficial específica ya documentada; no presentarlos como código producido durante el evento.
- Pegar enlace en la plataforma interna y comprobar que aparece público/con README. Los cambios posteriores a las 13:00 del sábado no sustituyen el commit guardado.
